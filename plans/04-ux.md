# Plan: User Experience Design

## Core Principle

**The content is the interface.** When reader mode is active, every pixel of screen space should show the user's content. The extension chrome should be nearly invisible.

## Extension States

The extension has three states the user needs to understand:

| State | Icon | Meaning |
|---|---|---|
| Inactive | Grey icon | Extension is not modifying this page |
| Markdown available | Green icon + "MD" badge | Page was served as native markdown |
| Reader mode active | Blue icon | Reader view is currently displayed |

### Key Design Decisions

- **Centered content column** — ~65-75 characters wide, optimal for reading
- **Generous whitespace** — margins give the content room to breathe
- **Optional TOC sidebar** — auto-generated from headings, collapsible, hidden by default on narrow windows
- **Minimal footer bar** — source type, token count, load time, theme toggle
- **No distractions** — no navigation bars, no social widgets, no ads

## Reader View Components

### Top Bar

A thin, dismissible bar at the top of the reader view:

```
┌──────────────────────────────────────────────────────┐
│  📖 blog.cloudflare.com  •  MD ✓  •  [Exit reader]  │
└──────────────────────────────────────────────────────┘
```

- **Domain name** — always visible so the user knows where they are
- **Source indicator** — `MD ✓` (native markdown) or `HTML →` (converted)
- **Exit button** — returns to the original page

| Property | Default | Configurable |

| Heading font | System sans-serif (Inter, system-ui) | Yes |

### Code Blocks

Syntax-highlighted with a subtle background, rounded corners, and a language label:

```
┌─ javascript ─────────────────────────────────┐
│ const r = await fetch(url, {                 │
│   headers: { Accept: "text/markdown" },      │
│ });                                           │
│ const md = await r.text();                   │
└──────────────────────────────────────────────┘
```

Copy button appears on hover.

### Images

By default, images are not loaded. Instead:

```
┌──────────────────────────────────────────────┐
│  🖼  Diagram showing the flow                │
│  [Load image]                                │
│  https://example.com/diagram.png             │
└──────────────────────────────────────────────┘
```

Click "Load image" to fetch and display inline. A global toggle in settings can enable all images.

### Tables

GFM tables are rendered as clean HTML tables with:
- Alternating row shading
- Header row with subtle background
- Border-collapse, no heavy borders
- Horizontal scroll on narrow viewports

| Shortcut | Action |
|---|---|

| `Escape` | Exit reader mode |

## Interaction Flows

### Flow 1: Markdown-native page (Auto mode)

1. User navigates to `blog.cloudflare.com/some-post/`
2. Extension modifies `Accept` header to include `text/markdown`
3. Server responds with `Content-Type: text/markdown`
4. Extension icon turns green, badge shows "MD"
5. Reader view activates automatically
6. User reads clean, styled markdown
7. User clicks "Exit reader" or presses `Escape` to see the original HTML page

### Flow 2: HTML page (Manual mode)

1. User navigates to `example.com/article`
2. Page loads normally (HTML)
3. Extension icon shows grey (reader mode available)
4. User clicks icon or presses `Ctrl+Shift+R`
5. Content script extracts content via Readability
6. Content is converted to markdown via Turndown
7. Reader view replaces page content
8. Icon turns blue, badge shows "R"
9. User reads clean article
10. `Escape` returns to original page

### Flow 3: Non-content page

1. User navigates to `gmail.com`
2. Extension is inactive (domain is in blocklist, or content is not article-like)
3. Page loads normally
4. No reader mode offered

## Accessibility

- Semantic HTML in reader view (proper heading hierarchy from markdown)
- Respects `prefers-reduced-motion` for transitions
- Respects `prefers-color-scheme` for auto theme
- High contrast theme option
- Keyboard-navigable popup and settings
- Focus management when entering/exiting reader mode
- All interactive elements have visible focus indicators
- Screen reader-compatible (headings, lists, links maintain structure)
